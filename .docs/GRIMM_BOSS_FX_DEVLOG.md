# 格林试炼 Boss 特效开发沉淀

本文沉淀试炼 Boss「格林」的弹幕、特效、原设重甲立绘与阶段编排经验。
猩红舞台与剧团特效借鉴 Hollow Knight 的氛围，人物比例与甲胄以用户提供的格林原设为准，不能混淆两者。
重点是 Canvas2D 能量特效的**材质方法论、渲染安全与验证手段**。
机制与表现严格分离：纯视觉迭代不得擅改数量、时序、伤害、覆盖率与碰撞；用户明确要求的机制重构单独记录。

> 最新机制以第 9～11 章为准：60／40 血量分界、24 秒生存时符、躯干碰撞中心。
> 历史尝试不等于现行参数；逻辑断言通过也不等于实机视觉、难度或性能验收。

## 2. 弹幕轨迹：16 向内旋为什么会变成直线

初版轨迹是"匀速外移 + 小半径内旋叠加"：

```
位置 = 朝向外移(speed*t, speed=460) + 内旋偏移(radius≤52 且指数衰减)
```

外移项的位移量比内旋半径大一个数量级，螺线被直线完全淹没，视觉就是 16 条直线。

**判据：复合运动中任何一层的位移幅值若远小于主导层，该层在视觉上等于不存在。**

修复后的轨迹（`BossAttacks.update` 的 mist 分支）由三部分组成，幅值互相可见：

1. 整体以约 0.6 倍速外扩；
2. 旋臂在生命周期内整体旋转约 1.618 圈（黄金比例角位移）；
3. 每发弹绕自身行进中心做"先外扩后回卷"的摆动（峰值半径约 118px，抛物包络）。

高速弹体的碰撞必须用**线段扫掠**（上一帧点到当前线段距离），不能只判当前帧圆心，否则短激光/高速弹跨帧漏判。

## 3. 视觉材质方法论（核心）

用户对特效的最高频负反馈是"廉价、塑料、像贴图、淡、没有光影感"。
经多轮迭代验证，以下规则决定特效是"贴图"还是"能量"。

### 3.1 第一判据：画线还是铸刃

描边圆弧/`fillRect` 光条无论叠多少层、调什么颜色，体量上都只是"线"，
与实体填充的能量体相差一个数量级。用户截图对比后这一点被明确确认。

- **厚刃/厚束必须实体填充**：沿运动方向切成大量扇片/段片，每片是闭合面。
- 斩击参考 `Player.renderDoomNormalTrail` 的做法：48～52 个环形扇片逐片填满扫过区域。
  - 截面宽度沿角度呈正弦曲线，中间最厚、两端收尖（当前格林斩击 `width=min(rad*.82,88)*sin^.72(π·u)`，最大约 88px）。
  - 每片先铺暗色实底立轮廓，再叠加色发光，杜绝发光层糊成灰白纸片。
- 激光同理：横向切成 42 段，每段的上下边缘由噪声函数给出，填充成闭合能量带，
  替代边缘绝对平直、宽度恒定的"贴图棍子"。

### 3.2 三层材质配方（暗核 + 加色光 + 白热芯）

每一个自发光特效都遵循：

1. **`source-over` 暗色主体**（近黑/深焰色，如 `#3d0d08`、`#070203`）：压住轮廓与体积。
2. **`globalCompositeOperation='lighter'` 加色光层**：暗红→主色→热色的径向/线性渐变，
   多单位齐射时每层 alpha 必须封顶，防止叠成一片白。
3. **白热芯/刃口**：最小面积、最高亮度（暖白 `255,240+`），是"烫"的来源。

辅助层：地面压暗带（亮束出现前先压暗周围地砖，对比即光影）、地面熔痕/焦斑、空气 bloom（超大半径极淡加色）。

### 3.3 不规则感：噪声驱动一切边缘

机械正圆、正梯形、等距刻度是"贴图感"的直接来源。统一用两类程序化扰动：

```ts
// 多频正弦叠加：边缘连续翻涌（激光束边缘/光带宽度/光丝蜿蜒）
const N=(u,o)=> .55*sin(u*9+o+t*.6) + .3*sin(u*23-o*1.7+t*3.2) + .15*sin(u*51+o*2.3+t*7)

// 稳定伪随机散列：断口/刻痕/火星/电弧"每帧不同但不闪烁"，相位用 h.phase 让每个单位各异
const Hh=(n)=>{ const s=sin(n*127.1+h.phase*3.7)*43758.5453; return s-floor(s) }
```

- 激光：黑束/内焰/三层泛光的边缘全部走 `N()`；束缘电弧用 `Hh()`，按 `floor(t*26)` 每 1/26 秒重排。
- 法阵火柱：左右边缘沿柱高 16 段用 `J(y)` 翻滚，顶部窄而稳、底部宽而乱。
- 法阵预警：5 段不闭合符环（长短/半径/角度错落）+ 7 段反向碎弧 + 11 根不等长刻痕
  + 内接三角剧团尖徽 + 呼吸染斑，替换原先机械的双虚线圆 + 8 等分刻度。
- 黑洞/雾团：24 点双频噪声轮廓 + 多层不同频率扰动，绝不画多边形描边框。
- 冲击环：半径沿圆周抖动，做双层错速扩散，而非正圆单环。

### 3.4 泛光、丝缕与流动

- 泛光不是一层大渐变，而是**多层带宽/频率/流速各不相同**的软边能量带。
- 束/柱内部要有丝缕：激光 3 条蜿蜒扭结的等离子丝（1 条白炽带辉光、2 条橙红）；
  火柱 7 条弯曲竖丝配 `setLineDash` + 持续变化的 `lineDashOffset`，亮段向柱顶窜升。
- 高亮点沿主体传播（激光 2 个跑动的脉冲结），避免通体均匀发亮。
- 边缘破碎件：斩击外弧 9 瓣向后翻卷的火舌；火柱两缘 10 截外翻短焰；斩击刃锋迸火星。

### 3.5 节奏包络

- 快出慢收：点亮用高次 ease-out（`1-(1-p)^3`），衰减用指数/幂函数慢收。
- 斩击刃锋从后缘扫向前缘，`freshness=exp(-(lead-midAngle)*1.15)` 让新刃亮、旧迹指数衰减。
- 击发瞬间（前 30% 左右）给独立的 `flash` 包络：外晕加宽、核心拉宽、电弧加长、墙端爆环。

### 3.6 配色专属：学手法，不抄配色

本项目已有两套自成体系的能量配色，**严禁混用**：

| 角色 | 底色 | 主色 | 热色 | 芯色 |
|---|---|---|---|---|
| 破灭魔王剑 | 深紫 `#60215f/#561653` | 玫红 `#bd258e` | 粉 `#f778bf` | 粉白金 `#fff1d9` |
| 格林剧团 | 黑焰 `#3d0d08/#070203` | 猩红 `#c4221a/#ff5c32` | 橙 `#ff682c` | 暖白 `#fff4e0` |

参考已有特效只能借鉴**分层、节奏、噪声、实填等手法**；
把参考特效的配色整套搬过来（曾把格林斩击画成魔王剑粉紫）属于明确事故。
遁入黑洞的暗紫涡线是用户认可的例外，与猩红体系并存。

### 3.7 各特效当前手法速查

- **slash（闪现斩）**：48 片实体扇片，近黑血底 + 深血红／猩红热层 + 暖白刃口；
  视觉半径为判定半径的 1.1 倍、最大厚度 88px；七团逆卷黑血雾、48/25px 双层泛光、30px 弧辉、
  翻卷火舌、刃锋火星与瞬闪；伤害范围不随装饰雾缘扩大。
- **laser（横向激光）**：预警只在最初一瞬画细提示线；激活为压光暗带 + 3 层噪声泛光
  + 噪声边黑束 + 2 层噪声内焰 + 3 丝缕 + 2 脉冲结 + 24 电弧 + 墙端冲击半环/放射芒/熔接点。
- **seal（井喷）**：预警见 3.3；激活为宽泛光 + 噪声边焦黑斑 + 6 锯齿裂隙 + 体积弱光梯形
  + 16 段翻滚火柱 + 7 条上升焰纹 + 柱缘火丝 + 热熔光 + 双层不规则环 + 10 火星。
- **smoke（遁入黑洞）**：纯黑吞噬核 + 加色暗紫光边 + 三缕逆卷雾丝 + 低频脉动，无硬边线。
- **mist（黑雾弹）**：不规则羽化雾团 + 三缕反向残雾 + 收小的猩红瞳；墙缘 alpha 羽化。
- **bolt（柱状弹）**：三段断裂抖动尾焰 + 黑色梭体 + 流动核线 + 白热弹头热晕。
- **感叹号预警**：粗壮圆角竖牌 + 独立圆点的经典可读造型，深酒黑 2px 描边压底、
  亮红渐变、杆身高光、约 8Hz 小幅缩放脉动（以本次预警经过时间为时钟）、轻微倾斜浮动；
  基础缩放从 1.15 渐增到 1.45，叠加脉动最大约 1.54，本体 alpha 0.94～1，永不闪灭；
  地面仅一枚小型暗红光斑。不用圆圈外框，不做过小过淡的抽象徽记。

## 4. 渲染安全：白屏事故复盘

### 4.1 事故根因

一次"激光提示线只显示一次"的特判误写成了全局判定，导致法阵在预警期被送进激活绘制分支；
此时进度值为负，冲击环用负半径调用 `ctx.arc`，Canvas **每帧抛异常**。
异常跳过了该特效的 `restore()`，`globalCompositeOperation='lighter'` 永久泄漏到
房间、玩家、UI，画面逐帧加色叠加直至全白且无法恢复。

### 4.2 强制规则

1. **所有半径/宽度先 clamp 或保证非负**，尤其由进度公式推导出的值。
2. 每个特效绘制必须 `save()`/`restore()` 严格配对（内部新增 save 必须数清楚 restore）。
3. 渲染分发外层兜底：进入前重置 `globalAlpha/globalCompositeOperation/shadowBlur`，
   绘制后（含异常路径）强制复位；建议 `try/finally`。
4. 单个特效报错不允许污染后续帧。

### 4.3 墙体越界

- 亮核/尾焰/雾缘泄到墙外黑区非常醒目。软体特效（mist/smoke/bolt/slash）统一在
  墙内缘（外扩约 8px 容错）建立 `clip()` 裁剪区；飞行弹体再叠加一层墙缘 alpha 羽化，
  裁剪边被淡出，不会硬切。激光自带墙内 `rect().clip()`。
- 沿主体循环的动效（流动高光）坐标取模必须处理负数：`((x % span) + span) % span`，
  JS 的 `%` 对负数返回负值，曾直接把亮块画到墙外。

### 4.4 其他易漏状态

`setLineDash` 也是画布状态：用了流动虚线必须在复位检查里覆盖（或保存/恢复配对），
否则虚线样式会泄漏给后续所有描边。

### 4.5 多单位齐射的性能开销

地面爆裂 16 柱同屏时出现过掉帧。按开销从大到小：

1. **`shadowBlur`**：Canvas 最昂贵的绘制属性之一。16 柱 × 5 段符环 = 每帧 80 次阴影描边。
   一律不要用阴影做辉光——`lighter` 下"同路径先描一条 2.5 倍宽的低透明色、再描细亮线"
   视觉等价且便宜得多。
2. **渐变对象**：`createLinearGradient/createRadialGradient` 不便宜，16 柱每帧重建 5~6 个
   就是每帧近百次对象分配 + GC。优化法：**把动态 alpha 从颜色 stop 中抽离，渐变做成峰值模板，
   透明度改由 `globalAlpha` 控制**；渐变本身可跨帧复用。
   - 用 `WeakMap<BossHazard,{ctx,map}>` 按 key 缓存（见 `BossAttacks.cachedGrad`），hazard 消亡自动回收。
   - 注意 Canvas 渐变在**创建时刻**按当前变换矩阵凝固为设备空间坐标；只有"位置/缩放每帧不变"
     的特效（固定的法阵柱）才能复用；移动中的弹体/激光脉冲不可缓存。
3. **路径点数**：小尺寸特效（半径 ~72px）肉眼分辨不出 40 点与 30 点的差别。
   冲击环 40→30、火柱边缘 16→12、焦斑 28→22、焰纹 10→8，齐射时省下上千次 `lineTo`。
4. **`setLineDash` 调用**：7 条焰纹各自不同 pattern 是每帧每柱 7 次切换；压成 3 种 pattern 循环复用。
5. **末期剔除**：淡出后段（如 `k>.8`，alpha 已 ≤0.3）直接跳过火星、火丝、裂隙这类细小件，
   它们在该透明度下本就不可见。

验证缓存是否生效：在 mock ctx 的 `createLinearGradient/createRadialGradient` 里计数，
16 柱完整生命周期的渐变创建数应等于"柱数 × 每柱缓存 key 数"（实测 96），而不是随帧数增长。

## 5. 验证方法论

用户会自行在浏览器调试，**不要启动调试器/开发服务器去占着**。本地验证走三层：

1. `npx tsc --noEmit`
2. `npx vite build`
3. IDE 诊断（GetDiagnostics）

机制/渲染回归用 stdio 内存断言（不依赖浏览器）：

- Windows PowerShell 下用 here-string 管道避免引号转义地狱：

```powershell
@'
<ESM 测试代码>
'@ | npx esbuild --bundle --format=esm --loader=ts | node --input-type=module
```

- mock `CanvasRenderingContext2D` 时重点记录：
  - 每次 `render` 后 `globalCompositeOperation==='source-over'`、`globalAlpha===1`、`shadowBlur===0`、虚线已清空；
  - `save/restore` 栈不下溢；
  - 非裁剪状态下所有顶点 `x` 不越出 `map.bounds`（alpha=0 的羽化绘制豁免）；
  - `arc` 半径不允许为负（直接 throw 以复现白屏事故）；
  - 统计每帧 `fill()` 调用数，确认实体填充特效没有退化成"几条线"。
- 场景至少覆盖：16 弹、16 法阵齐射、14 激光齐射、连斩、斩击+黑洞、全部混合齐射，跑完整个生命周期。

## 6. 维护原则

- 改视觉不动数值；改之前先确认 `BossHazard` 字段（delay/duration/rx/ry/angle/phase）的机制含义。
- 新特效默认套用：噪声边缘（`N`/`Hh`）+ 暗底实填 + `lighter` 加色 + 白热芯 + 快出慢收包络。
- 配色只能从所属角色的配色表取；跨角色借鉴仅限手法。
- 多单位齐射的加色层一律 alpha 封顶，宁可暗一点也不要糊白。
- 任何新画布状态（filter、dash、shadow、clip）都要纳入断言的复位检查。

## 7. 猩红圣堂斗场：主题房间与氛围（2026-10，已实机验收通过）

> 验收结论：暗度、火盆、余烬、帷幔与 BGM 的整体压迫感一次通过，无需回调。
> 下列数值即**验收档**，后续修改前先对比它们。

### 7.0 验收参数档（用户认可，勿轻易动）

- 环境罩：center `0.6`（+呼吸 ±0.022）/ edge `0.9`，色 `cc='18,5,9'`、`ec='4,1,3'`；阶段脉冲时最多挖亮 0.3/0.16。
- 玩家灯：默认灯半径 ×`0.92`，色 `#ffd6b2`，tint `.08`。
- 火盆光：7 只，r `300`、power `.9`、`#ff8038`、tint `.24`、flicker 开；Boss 光源 r `172`、power `.5±.08`、`#ff5230`、tint `.22`。
- 余烬 34 粒三层景深：尺寸 3~9、上升 10~34 px/s、基准亮度 .3/.55/.85；北墙根(y<108)从南墙(y=874)重生。
- 暗角：透明中心半径取短边 `.34`，.72 处 `rgba(26,4,10,.34)`，末端 `rgba(10,1,5,.74)`。
- 呼吸/脉冲：全场 lighter 猩红呼吸 alpha ~`.028±.012`；阶段脉冲以 Boss 屏幕坐标为中心，中心 `.30`、衰减率 `0.8/s`（约 1.2s）。
- 房间外底色 `#0a0408`（原矿洞 `#090911`）。

### 7.1 架构

- `ScriptedRoomSpec.theme?: 'grimm'`；`RoomRuntime` 构造期按主题选择烘焙器：
  `createRoomTextureTrial`（新文件 `art/roomTextureTrial.ts`）替代 `createRoomTextureE`，
  同时 `torches/vents=[]`（火盆是自定义光源，不用火把槽），`RoomRuntime.render` 的矿洞落尘/水滴按主题跳过。
- 烘焙器只画静态：近黑打磨黑石大砖（错缝横列、砖缝透一线暗红）、中央低透明度巨型仪式法阵
  （多层环/16 刻度/倒三角/四正位节点，alpha 0.08~0.32，绝不抢弹幕）、三面黑石裙墙、
  北墙黑石立面+暗红垂坠帷幔窄边（暗金横杆/波浪下摆/金穗）+石台压顶、七只三足铁火盆的静态铁座。
- 动态全部在 `TrialModule`：火盆焰体（缓存光晕精灵 + 四层水滴焰）、34 粒三层景深余烬、
  自有 `CaveLight` 光照 pass、屏幕暗角/呼吸/阶段脉冲。
- 矿洞主题用冷青蓝环境罩；`AmbientLevel` 新增可选 `cc/ec`（'r,g,b'）支持暗红酒黑罩，
  不改默认色，矿洞零影响。
- 试炼房**没有**走 `litRoom`（那是明亮暖档）；环境压暗档由 TrialModule 每帧直接给
  CaveLight：中心 ~0.6、边缘 ~0.9，四角近黑，玩家可视光圈收窄 8% 并转暖白。

### 7.2 氛围配方

- 光源表 = 暖白玩家灯 + 7 火盆（r300 power.9，#ff8038，customLights 自带 ±10% 焰息）
  + Boss 身上一团呼吸猩红光源（#ff5230）。黑暗靠光源挖洞，不要靠全局染色。
- 屏幕空间：暗角渐变按视口尺寸缓存；全场极弱 `lighter` 猩红呼吸（alpha ~0.03）；
  Boss 阶段切换以 Boss 屏幕坐标为中心打一次径向红光脉冲，约 1.2s 衰减，同时环境罩短暂被挖亮。
- 余烬：软发光点一律预渲染成离屏精灵（`makeGlowSprite`），运行时只 `drawImage`；
  三层景深给不同的尺寸/上升速度/基准亮度；水平只在锚点上正弦摆动，升到北墙根从南墙重生。
  严禁每粒每帧新建渐变或开 shadowBlur。

## 8. 原设重甲、黑血披风与连续骨架动作

### 8.1 失败经验：高耸不等于细长

第一轮收窄过度，把大叠肩变成两个小护肩、胸腹变成束身甲，厚围领消失。
用户原设强调的是宽厚肩胸、不对称叠甲、头盔嵌入围领的重量感，不能仅凭“高耸”二字拉长素材。
修正为左肩大面积叠甲、右肩尖棱带厚底座；胸腰保持体积，腿甲适当缩短加厚。
原设截图是人物结构的依据，场景主题不能反过来替换人物身份。

### 8.2 近黑凝血布料

- 普通鲜红披风会破坏黑暗感；采用近黑血底，褶峰仍有红色可读性。
- 当前布料渐变：`#29060d → #140307 → #0b0205 → #050103`；翻折 `#410914/#2b050d`；残条 `#30050e/#1e0309`。
- 宽褶面用实体明暗，不靠亮红轮廓线；不等长裂口、撕裂布瓣与细长残条构成破败感，避免均匀锯齿下摆。
- 三阶段损毁通过甲片形状缺失与胸甲暗层暴露表达，不只是换色：二阶段左肩缺片、胸口裂缝；三阶段右肩尖甲缺损、胸甲进一步剥落。

### 8.3 肩、肘、腕分段联动

- `GrimmRigMotion` 每个 Boss 实例单独持有，由 `createGrimmRigMotion()` 初始化，不允许全局共享动作历史。
- 展示骨架保存 shoulder/elbow/wrist/left/leftElbow/lean/cloth；目标姿态与当前姿态用指数插值衔接。
- 时间来自游戏 clock；暂停重复 render 时 dt=0，不继续推进动画。插值 dt 上限 .05 秒。
- 常态／施法插值率 18，斩击 45，披风 8；披风慢于手臂，表现惯性而非同步摆板。
- 施法用非持剑臂抬起、肘部展开、手掌张开；长剑留低位。奔跑有腿甲交替与躯干前倾；斩击肩肘腕先后加速。
- 固定 `Path2D` 用 Map 缓存，避免每帧解析甲片路径。动画角度用上下文变换，不把时间拼进路径字符串造成缓存无限增长。

### 8.4 背后引导光轮

- `bossCastHalo.ts` 提供 `BossHaloStyle {blood, edge, sides}`，格林为血红三角系；跨 Boss 共用分层与节奏，但不强制共用配色、徽记。
- 外层三重断裂符环、错长蚀刻片与泛光烘焙到 320×320 离屏画布，按样式对象缓存。
- 外轮正转、几何框反转、内部纹脉逆卷；纹理缺口和微扰破除光滑圆盘的贴图感。
- 展开半径 `26+112*(1-(1-progress)^3)`；常规引导结束 alpha 在 .32 秒内消退。
- 先画光轮再画人物，让身体遮住中心；不用满屏白闪或堆粒子代替几何纵深。

## 9. 两段血量战与24秒生存时符（现行60／40分界）

### 9.1 状态流程与破功门控

| 环节 | 血量／时长 | 行为 |
|---|---|---|
| 一阶段 | 100% → 40% | 原有四套技能 |
| 首次破功 | 1 秒 | 无敌、清攻击、黑洞传送中央 |
| 二阶段 | 锁40%，24 秒 | 「时符」爱与疯狂誓约，无敌生存 |
| 再次破功 | 1 秒 | 清时符弹幕、静止引导 |
| 三阶段 | 40% → 0% | 五技能池与原技能变种 |

- 早期70／30方案与旧70%／35%阶段刻度均已废弃；血条当前只留40%刻度。
- `battleStage` 独立于 hp 比例；不要声明 `private phase`，父类 Enemy 已有同名私有字段，曾导致继承类型错误。
- 一阶段在调用父类 `takeDamage` **之前**截断伤害到40%，避免父类先执行死亡分支再“复活”。
- hidden、break、二阶段统一由 `canBeHit` 禁止受击，所有正式武器结算复用这一门控。
- 阶段入口清理旧攻击、预警与速度；退出时符清弹后允许纯视觉 smoke 过渡，不能把“清场”误写成禁止任何演出实体。
- 第一段过渡开始在原位置开同款黑洞；经过 .35 秒，坐标移到地图 bounds 正中，中央开第二黑洞。
  角色先淡出，再在约 .25 秒内显现；全过程仍占1秒，不额外拖长24秒时符。

### 9.2 三幕主题与当前节奏

- 0～8秒：血红与黑血两侧发射印，每组两套10向曲线弹，延迟差 .13 秒，成对追随。
- 8～16秒：旋向反转，黑血弹开始减速回卷，转向前有收缩环提示。
- 16～24秒：外放与回流交错，每隔三组补有缺口的18向花瓣弹；22秒后不再新增普通弹组。
- 组间隔当前为 .75 秒（寿命延长前曾是 .55 秒）；每幕起始 .45 秒暂停发射，旧弹继续运动。
- 12秒、19秒分别安排一次五线黑域射线预警，13秒、20秒左右击发。
  用独立 `spellRifts` 计数与 while 跨阈值判断，避免低帧率漏发／重复。
- `TrialModule` 显示符卡名、剩余秒数和无法造成伤害提示，所有文本来自 i18n。

## 10. 弹幕行程、方向扫场与黑域裂束

### 10.1 短寿命与回流半径不足的根因

旧时符外放弹4秒后即消失，回流弹最大距离为 `speed*duration/π`，175px/s × 5秒只有约279px。
结果是中心演出密集而贴墙只遇到少量弹，不能靠增大发射数量修复。

现行参数：
- 中央时符行程 `reach=房间完整对角线/2+50`，默认房间约915px。
- 外放弹 `distance=speed*t`，寿命 `reach/speed+1`；花瓣弹同理，碰墙清理。
- 回流弹最大距离独立为 reach：`distance=reach*sin(π*u)`，寿命8秒；中点速度自然为零后折返，避免瞬间掉头。
- 普通16向雾弹、24向光柱寿命按完整房间对角线／有效速度＋.3秒计算；雾弹有效外移速度是 speed×.6。
- 三阶段雾弹寿命为去程的两倍，以正弦 travel 参数沿原曲线往返，锁定发射原点，不追踪移动中的 Boss。
- 回流弹不能在第一次碰墙时销毁，否则返程永远不存在；当前保留其生命周期，绘制在墙内裁剪。
  这意味着部分回流弹会在墙外运动后重新入场，是现行行为，不应误记为沿墙折返。
- 延寿会增加同屏存量，必须连同发射间隔、清理、裁剪与实机帧率一起检查，不能只证明“飞得远”。

### 10.2 三阶段高速光柱与方向激光

- 光柱连续两轮，每轮24向，间隔 .22秒；第二轮角度错开 `π/24`（7.5°）。
  三阶段关闭初期追踪修正（fixed），否则第二轮会被追踪扭回原轨迹。
- 激光从“束角＋法向投影偏移”生成，支持八种推进方向；法向范围由房间宽高在法向上的投影确定。
- 50%概率双组，第二组当前固定与第一组相差90°，排除同轴反向组合；单组14束，双组各7束，总数仍14。
- 双组宽度共享覆盖预算，第二组延迟错开 .045秒。覆盖预算不等于已证明任何站位都安全，仍需实机测躲法。
- 旋转束碰撞使用局部坐标：沿线 `dx*cos(a)+dy*sin(a)`，垂距 `-dx*sin(a)+dy*cos(a)`。
- 渲染先做世界空间房间裁剪，再旋转局部束坐标，不能旋转后继续使用世界横向边界，否则会墙外泄漏。

### 10.3 黑域射线：伤害窗口与视觉寿命解耦

- 每次5条：方向 `i*π/5±.09`、法向偏移初始±190px。用角度与法向偏移替代随机 k/b，自然支持垂直线。
- 与玩家当前法向距离小于64px时，将线偏移到玩家法向位置±90px；这只提供当前位置安全间距，
  不是完整的可达路径／交点死局求解，不应夸大为已证明所有随机布局安全。
- 预警全程1秒，刻线固定；击发后 .04秒内掠完整条线。
- `duration=.65` 是视觉总寿命，`activeDuration=.18` 是伤害窗口；延长余波不能延长伤害。
- 碰撞沿射线已展开的 head 截止，并保留跨帧激活结算，避免视觉没到就伤人或短束漏判。
- 击发只在 fired 首次置位时触发 impact＋slash 音效与 .22震屏；五线齐射的实际音量叠加还应实机检查。
- 外观用厚黑核、血色破碎边、宽泛光及扩散碎片区别于连续白炽激光；余波持续衰减而非一闪即没。

## 11. 躯干碰撞中心与脚底绘制锚点

格林变高后若继续用脚底 x/y 作为受击中心，会出现玩家攻击身体却打不到的错位。
当前不逐一改武器命中公式，而把格林实体 x/y 定义为躯干中心，素材单独保留脚底偏移：

- `footOffset=90*CONFIG.tile/48`；构造器接收原脚底出生位置，传给父类的 y 减去 offset。
- `drawGrimm` 使用 `entity.y+footOffset`；背后光轮与地面施法椭圆也按其对应视觉锚点补偿。
- 时符中央传送现在把**躯干实体中心**放到 bounds 正中，不再把脚底放到正中。
- 碰撞半径仍38，正式近战／符卡／光刺复用实体中心；这是受击与移动碰撞坐标语义的变更，不只是素材偏移。
- 后续验收需检查贴墙移动、脚底越界、y-sort 遮挡、黑洞与感叹号位置、发射点与光源对齐。
  这些依赖脚底的系统不能因为类型检查通过就认为已自动正确。
