## 1. 技术路线

- **纯 Canvas2D 代码绘制**，无 PNG / 精灵图 / Spine：平滑矢量、纯色面 + 细墨线。
- 角色动作是程序化骨骼，姿态无限连续；换装靠分层叠加，不依赖预制帧动画。
- 总体规格：**2 头身 Q 版**，圆钝外轮廓、慵懒呆萌表情（参考主角＝蓝衣少年）。
- 不引新依赖；表现层一律补丁式修改（单功能面改动），禁止整文件重写。

## 2. 三层架构（`src/game/art/rig/`）

| 文件 | 职责 |
| --- | --- |
| `skeleton.ts` | `PlayerPose` 纯数据：骨角（spine/头/四肢）、root 偏移、aim、相位 spare 等 |
| `playerAnims.ts` | `PlayerAnimator` 状态机：吃 `(speed, moveAngle, aim, armed, armAim)`，每帧 `build()` 产出 pose |
| `playerRig.ts` | `drawPlayerRig(ctx, x, y, pose, opts)` —— 唯一绘制入口；含全部形状/色板/装配顺序 |
| `weaponRig.ts` | 武器绘制，在**手心局部系**作画，经 `opts.drawWeapon` 回调挂载 |

调用方：`Player.ts` 正常绘制（约 :845）与移动残影（约 :772，`opts={}`）。

**数据流向**：输入状态 → 动画机算骨角（纯数据）→ rig 只负责画。
rig 内不许写状态机逻辑，动画机内不许碰 ctx。

## 3. 坐标系与角度约定（踩坑最多，务必背熟）

### 3.1 基础约定

- 骨角用 `atan2` 标准角：**π/2 = 垂直向下**，0 = 屏幕右，π = 屏幕左。
- 躯干是独立局部系：`save → translate(0, PELVIS_Y) → rotate(spine) → 画衣服 → restore`，
  该系 **+x 指向角色头顶方向**。
- 四朝向由 `moveAngle` 八向归一 + `DIR_HOLD` 迟滞产生：`down / up / left / right`。

### 3.2 世界角 vs "朝左基底局部角"（第八轮武器翻转 bug 的根源）

骨角字段有**两种语义**，翻转规则完全不同：

| 语义 | 字段 | left/right 产出的值 | right 朝向如何翻 |
| --- | --- | --- | --- |
| 世界角 | `aim`、`spine`、`head`、**挥击臂角**(`armAim/lock`)、持械 idle 臂角 | 符号不同 | `ma(a)=π-a` 后再被根层 scale 翻（双翻还原） |
| 局部角 | 走路的腿角、徒手摆臂角 | **完全相同** | 只被根层 `scale(-1,1)` 翻一次，**禁止 ma** |

- right 朝向：rig 根层 `ctx.scale(-1, 1)` 整体镜像。所有形状按"面朝左"画一遍即可。
- 渲染端：`drawHead(..., ma(pose.aim))`、`rotate(ma(b.spine))` 保留 ma；
  **drawLeg / drawSleeve 的骨角一律传原始值**。
- 挥击/持械臂角是世界角：在 **playerAnims.build 输出前**统一转换
  （`if (dir==='right') { upper=π-upper; lower=π-lower }`），渲染端不做第二套判断。
- 持械手世界锚点（给外部世界系消费者）：位置 `mirror ? -x : x`，角度 `mirror ? π-a : a`。

> **铁律：极性只能按语义在一个地方翻转。**
> 多处翻 = 双重翻转 = 互相抵消（症状：动作永远偏向屏幕固定一侧）。
> 判别法：看动画端该角度在 left/right 下是否产出相同值——相同＝局部角；符号相反＝世界角。

## 4. 部件装配顺序（画家算法）

1. **远侧腿**（最底层；身后腿被衣摆遮挡是正确透视）
2. **侧身远袖**（`hideLevel=1`，只露窄白衬里）
3. **躯干**（脊柱局部系）：羽织背片 → 衣身 → 领座/后领 → 衣摆白滚边
4. **近侧腿**：
   - 侧身 → 画在躯干**前**（前迈的脚在敞开的前襟前方，不被长摆盖住）
   - 正/背面 → 画在躯干**底层**（裤管只从衣摆/开衩下露出，绝不穿衣身）
5. **头**（含脸/发/呆毛）
6. **双臂前层**：down/up 两袖全画；side 只画胸前近袖；持械武器在近袖手心回调

两个衔接要点：

- **头身不能分离**：头底缘与衣领之间必须有"领座"填补——正面两片肩领 + 白 T 圆领 +
  一截脖子；背面背片顶部收成圆弧后领，后颈插进领里。颈顶要埋进下巴。
- **同色部件相接必垫墨边**：袖子画在同色羽织衣身前，先画一道 alpha 0.5、宽 w+1.4 的
  袖底墨边，否则糊成一片。

## 5. 关键绘制技法

- `tube()` 粗管肢体：两端半圆帽 + 矩形主体 + 中线/墨边；腿宽 `W_LEG=4.6`。
- `drawSleeve(ctx, sx, sy, upperA, lowerA, far, dir, onHand?, hideLevel=0)`：
  - `hideLevel` 三档：**0** 完整白袖护 + 肤色手；**1** 窄白衬里（宽 1.15）；**2** 全藏。
  - 背面两袖统一用 haori 主色（`far && dir!=='up' ? haoriDark : haori`）。
- 肩锚常量：正/背面 `perpX/perpY*SHOULDER + SHOULDER_Y`（SHOULDER=4.8，手落在衣身侧缘外）；
  侧身远 (4.6,-6)、近 (-4.0,-6)，严格同高。
- 头部分三套：`drawHeadFront / drawHeadBack / drawHeadSide`；right 向靠根镜像复用。
- **脸的统一语言**（正脸侧脸必须同款，别把侧脸画成大眼娃娃）：
  半垂慵懒小眼——粗重圆弧上眼睑压住虹膜上缘、虹膜只露下半、一个小高光；
  短平弧眉；圆钝小鼻（0.4px 凸起，禁止翘鼻尖/鸟嘴）；内嵌小圆嘴 + 微笑弧；腮红。
- **鞋勾脚修正**：鞋局部系 `rotate((thighA + shinA) / 2)`——回勾半个屈膝量，
  鞋底始终近水平朝下，后蹬时鞋头不朝天。
- MockCtx 自检坑：满圆 `ellipse` 必须拆成两段 180° 弧（否则 SVG A 弧扫掠标志非法）。

## 6. 动画步态模型（playerAnims.build）

相位：`φ = walkPhase`，`sinF = sin φ`、`cosF = cos φ`；far/near 两腿反相；`w` 为走姿权重。

### 6.1 侧身（left/right）走路

- **支撑相**（脚在地上，`cosF<0` 半周）：腿基本伸直；后蹬顶点直腿、脚跟真正探到身后
  （身后必须看得见脚，否则就是"单侧甩腿/滑步"）。
- **摆动相**（脚离地，`cosF>0` 半周）：平方权重把弯曲集中在中点（高抬收膝），
  前后两个顶点近伸直：
  `bend = 0.08 + max(0, ±cosF)² · 0.85 · w`
  （near 的 cosF 取负号）
- 摆幅**近对称**：前 0.50 / 后 0.42。过度不对称（如 0.66/0.18）+ 后顶点屈膝
  会让脚全堆在行进侧，观感就是滑步。
- **不要**加 rootX 周期前送补偿：世界位移恒速，身体周期前后晃本身就是打滑。
- 腿角语义＝局部角（见 §3.2），渲染端只靠根层镜像。

### 6.2 俯视（down/up）走路

俯视看不到前后纵深，直接摆腿会像"左右甩"。用**原地踏步**：
大腿抬起角与小腿反向屈角相互抵消，让踝点近似只做垂直起落（峰值约 2.8px），
两脚在身下左右分列、交替抬落。例：
`thigh = π/2 + 0.06 + α`，`shin = π/2 + 0.06 - 0.9α`，`α = 0.74·max(0,sinF)·w`。

### 6.3 臂与 idle

- 徒手足与对侧腿反相自然摆臂；外展 0.17 弧度。外展角必须随 `perpX` 翻转
  （down=-1 / up=+1），否则背面变拱手。
- 持械：挥击时大臂跟向武器角 97%、`lower = armAim` 锁直；持械 idle 武器轻持腰前
  （raise 0.5，不横抱到胸前），走起步逐渐回到指向角。
- idle：脊柱呼吸、换重心、头发/衣摆微摆；构造自检姿态时必须先 `speed=200` 跑 30 帧
  过 `DIR_HOLD` 迟滞，再 `speed=0`，否则朝向永远是 down。

wave      #dce8ff   青海波/衣摆滚边

- 线宽 0.7~1.4px，圆头线帽、圆角线接；阴影用同色系加深，不用纯黑大色块。

- 新角色沿用同一套规格，只换色板/服装结构/发型。

## 8. 视觉自检管线（改动后必走，没过不准宣称完成）

2. 打包运行：
   `esbuild entry.ts --bundle --platform=node --format=cjs --outfile=bundle.cjs && node bundle.cjs`

   --virtual-time-budget=6000 --window-size=1400,900
   --screenshot=shot.png file:///.../preview.html`

4. Read 截图逐帧核对；标准检查集：四向 idle + 侧身走 12 帧 + 正面/背面走若干帧；
   持械改动要加 10 格左右/斜向挥剑场景。
5. 收尾：tsc 零输出 → GetDiagnostics 零诊断 → DESIGN_MEMO 末行追加 →

## 10. 装备换装接入（装束槽 outfit ×1 + 饰品 trinketA~D ×4）

- 装备数据源：`CharacterProfile.equipment`（账号级存档；槽位定义见 `src/shared/equipment.ts`）。
  物品侧：装束声明 `equipSlot: 'outfit'`；饰品声明虚拟值 `equipSlot: 'trinket'`
  （trinketA~D 四槽同型，门控在 `slotAccepts`）。
- **装束＝分层换装**：在躯干绘制段（§4 第 3 步）按 outfit id 调对应服装绘制器，
  替换或叠加羽织层；发型/脸保持角色本体。装束自带的鞋袜在腿足段叠加。
- **饰品＝锚点挂载**：在 rig 常量里定义锚点（耳侧、发顶、胸前、后背、腰等），
  饰品绘制器在锚点局部系作画（范例＝weaponRig 在手心局部系）。
- rig 需要读装备时通过 `opts` 传入快照（与 `drawWeapon` 同款风格），不直接 import profile。
- 每套新装备必须走 §8 自检：裸装 / 装束各一件 / 四饰品槽各一件 × 四朝向。

## 11. 灵梦迭代经验（2026-10-02，当前规则优先于早期试验记录）

### 11.1 遮挡关系必须按最终需求验收

- 背面最终要求：**垂臂时长发全遮袖口和手，施法张臂时才露完整袖管与手**。早期“盖臂露手”的圆弧缺口方案已废弃，不能再按旧记录复原。
- 后脑与披发最终共用头部局部系的一条连续路径；用两个局部系的发片加连接块遮接缝，会产生台阶和布片感。
- 两侧发饰下面必须有独立束发轮廓、发梢和明暗，不应把发饰直接贴在一整片发幕上。
- 背面双肩横向极性与正面相反，施法目标角必须交换，否则双臂向中间交叉；恢复袖管绘制不等于姿态正确。
- 裙装近腿不得照搬敞襟羽织的前层腿：**两腿先画、裙身压住大腿上段**。侧面双鞋辨识靠远腿微小后移，不靠把整条近腿放到裙子前面。
- 侧面远鞋略小，远袜红环与第二道脚踝红带可因遮挡省略，避免露出红色碎片像裙色泄漏。

### 11.2 线条、发束与材质

- 保留主外轮廓；内部改细棕色边、同色暗面，不能所有部件都套粗黑线。
- 红饰用细窄平头布带和缝边，避免 round 粗线形成胶棒；袖口用白色扇形折面，不用黑边椭圆圆环。
- 刘海先设计少量顺向大束，避免密集回钩、深瓣谷和束发末端黑色圆团。
- **减线必须补色面**：只删除黑线会变平。亮面沿分束中心到发尖展开，暗面表示束间叠压；避免孤立椭圆亮斑或每束一根等粗亮线。
- 正侧发型必须共享流向逻辑。背面已确认的造型不因正脸修订而反复重画。
- 头部下移缩短头肩距离时，侧颈与白领同步调整；领巾要有垂胸双片，不缩成小黄点。

### 11.3 正脸 B 方案与侧眼

- 同一正式头壳、脸形、发色与腮红做 A/B/C/D 对照，主人选定 **B 柔和圆杏仁**，正侧实装，无嘴。
- 眼裂先画，再裁切虹膜；上眼线用内细外渐宽的填充面收尖，不用均匀粗弧覆盖完整圆眼珠。
- 虹膜上深酒红、下亮玫红，保留主高光与小反光；眼尾朝外，光源高光不能跟着左右眼一起反向。
- 侧眼需要专门的透视压缩，当前横向 0.78、纵向 0.8；朝左时眼尾应在耳侧（局部右侧），不能直接镜像正脸左眼。
- 候选页 `preview/reimu-face-lab.html` 必须复用正式头壳；选定前不替换默认五官。正式四向页 `preview/reimu-rig.html?detail` 检查大倍率结构，普通页检查小尺寸与走路。
- **截图存在不等于验收通过**：明确核对遮挡、接缝、姿态、轮廓和小尺寸辨识；不能把“没有路径异常”宣称为“造型正确”。

## 12. 梦想封印音频迭代经验（2026-10-02）

### 12.1 从失败候选到选定 I

- 初版五声音阶铃音＋低频咚＋扫频噪声被反馈缺少符卡感；A/B/C 偏柔，D/E/F 又偏短脆，像 kick/snare/hit 的拼接。
- 错误：把“爆破爽感”理解为更尖的瞬态、更短的衰减、更少混响；单颗降调正弦与短噪声不能提供完整爆体。
- G 先解决声音主体：宽频破裂、中低频翻滚、约 1.65 秒声体、0.3 秒五爆尾声衔接、末爆减速延长、同源反射与混响。主人确认声场和力量方向正确后，才分化色彩。
- H/I/J 保留 G 主体，只改变开印、爆后泛音与收束；主人选定 **I 梦幻光弹**：展开光泽、微失谐泛音、光弹尾声，不是逐级提示旋律。

### 12.2 可复用设计规则

- 爆炸结构：起爆入口 → 声体膨胀 → 中低频翻滚 → 逐渐变暗的扩散尾声。起爆只是入口，不能抢掉主体。
- 声体用按采样率设置的一阶滤波分出约 240/1800/6200Hz 三层，叠加起伏包络与膨胀峰；归一化避免偶发峰值失控，不靠盲目提高总音量。
- 同源爆体在 75/140/235ms 产生衰减、降亮度、左右错开的反射，叠加卷积混响；有 rev 参数不等于听感有空间，必须实际试听。
- 魔法色彩建立在饱满爆体上，覆盖发动、连爆与收束；不能用五颗铃音替代 bomb 的重量。
- 试听页 `preview/dream-seal.html` 提供候选、G 基础版、旧版对照、音量与防叠播；助手没有听到输出时只报告代码/类型检查，不宣称听感优秀。**用户试听选择是音色验收依据**。
- 正式入口 `sfx.dreamSeal(pans)` 使用 I 色彩；RoomRuntime 首爆只调用一次，传入实际五爆声像，音频时钟调度后续 0.3 秒连爆。取消原逐爆 `prismaBlast` 调用，避免旧音叠播。
- 试听含 0.85 秒聚气延迟；正式首爆 release=0，尾韵用 release 相对时间，不能把试听延迟直接搬进游戏导致音画错位。
- 本次只通过静态接线和类型检查；正式剧情音画同步及混音仍需实机验收。音频时钟与游戏时钟在暂停/后台时可能分离，未来扩展必须显式考虑取消与暂停，不能宣称目前已解决。
